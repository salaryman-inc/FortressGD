Export a Godot game that stock GDRE/KeyDot cannot one-click recover, without maintaining a fork. Designers keep the official Godot editor. Custom export templates are relinked per project in a prebuilt build image, compiled once from a pinned Godot tag plus a small patch quilt. Production exports refuse to ship source, and `fortressgd verify` fails CI if they did.

<Aside type="caution" title="What this is not">
	FortressGD raises the cost of automated recovery. It does not make a local client unextractable: a debugger can still dump decrypted resources from a running game. See the [threat model](reference/threat-model/).
</Aside>

## Features

<CardGrid>
	<Card title="Export hygiene" icon="approve-check">
		Production presets skip GDScript text, C# source, `.pdb` symbols, DCC work files and source maps. `fortressgd verify` lists packed paths and fails CI if anything leaked.
	</Card>
	<Card title="Derived encryption key" icon="seti:lock">
		The PCK AES-256 key is derived from the project secret (`FGD-KDF-1`) and stored by code generated per build, so an extractor written for one build is not meant to work on another. The secret itself never ships.
	</Card>
	<Card title="Per-project pack dialect" icon="puzzle">
		Pack magic and index field order come from the project secret, so stock GDPC parsers cannot list the pack.
	</Card>
	<Card title="GDScript mangling" icon="pencil">
		Strips comments and debug calls, and renames user identifiers with an HMAC keyed from the project secret.
	</Card>
</CardGrid>

Supported engine tags: **Godot 4.6.2** and **4.7.2** stable. Protected platforms in v1: **Windows** and **Linux** (x86_64).
